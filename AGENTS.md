# AGENTS.md — AI Agent Instructions

## Project purpose

This repository provisions a **GitHub Actions self-hosted runner** inside a
Proxmox LXC container using Terraform. The runner is registered with a GitHub
repository or organisation so that CI jobs can execute on your own hardware.

## Terraform workflow

```bash
# Source credentials first
source .envrc

# Standard workflow
terraform -chdir=terraform/lxc init
terraform -chdir=terraform/lxc plan
terraform -chdir=terraform/lxc apply

# Or use just recipes
just init
just plan
just apply
just deploy   # init → validate → apply-auto
```

Always run `terraform plan` before `terraform apply`. Never skip it.

## Who owns what

**Terraform owns infrastructure only** — the LXC container, its resources, its
network, and its DNS. **Ansible owns everything inside the container** — runner
binaries, registration, systemd services, the health check and disk cleanup.

Runner installation used to live in a `remote-exec` provisioner that stopped and
deleted *every* runner on any token change. An apply during CI killed live jobs,
and a failure part-way through left the host with zero runners. That is gone.

`terraform.tfvars` remains the single source of truth: Terraform projects the
runner settings into `ansible/group_vars/gh_runner.yml`, which Ansible
auto-loads. Never hand-edit that file — it is regenerated and gitignored.

## Runner registration tokens

Tokens are **only needed for runners that are not yet registered** — a new
target, a higher `github_runner_parallel`, or a rebuilt container. Everyday
convergence (config changes, health-check updates, drift repair) needs none:

```bash
just converge          # no tokens, safe to run during CI
just converge-check    # dry run
```

When you genuinely are adding runners:

```bash
just converge-tokens   # mints one token per target, in tfvars order
```

Better still, set a PAT so the box never needs a human for recovery:

```bash
export TF_VAR_github_pat="ghp_..."   # repo + workflow scope
just runner-apply
```

The PAT is written to `/etc/github-runner/pat` (mode 0600) and lets
`runner-health` mint its own registration tokens. Without it, a runner that
GitHub drops stays dead until someone runs `just converge-tokens`.

Obtain a token manually from:

- **gh CLI (org)**: `gh api --method POST /orgs/{org}/actions/runners/registration-token --jq '.token'`
- **gh CLI (repo)**: `gh api --method POST /repos/{owner}/{repo}/actions/runners/registration-token --jq '.token'`
- **UI**: Settings → Actions → Runners → New self-hosted runner

## Resilience machinery

Two systemd timers run inside the container, both installed by the Ansible role:

| Unit                   | Schedule                  | Purpose                                                                 |
| ---------------------- | ------------------------- | ----------------------------------------------------------------------- |
| `runner-health.timer`  | every 5 min + 2 min after boot | Checks DNS → GitHub API → per-runner liveness → registration → disk |
| `runner-cleanup.timer` | daily (randomised)        | Prunes stale `_work` dirs, `_diag` logs, journal, apt/pip/npm caches     |

`runner-health` escalates: restore the pinned `/etc/resolv.conf`, restart
services once connectivity returns, restart a dead service, and finally
re-register a runner GitHub has dropped (PAT required). Both log to the journal
under the `runner-health` and `runner-cleanup` tags.

```bash
just health       # run the check now and see its verdict
just health-log   # recent health + cleanup history
just timers       # timer schedules
just cleanup      # reclaim disk now
```

Neither script ever touches a runner that is executing a job — `gh-runner-drain`
waits for the `Runner.Worker` process to exit first. The same guard makes
`just converge` safe to run mid-CI.

## DNS

`dns_servers` is pinned in Terraform via the container's `initialization.dns`
block. This is load-bearing: Proxmox rewrites the container's
`/etc/resolv.conf` from the **node's** DNS on every container start. On
2026-05-13 that pointed at an unreachable WireGuard gateway and every runner
silently stopped taking jobs for ~1.5 days while reporting `active (running)`.
See `docs/incidents/2026-05-14-dns-outage.md`.

A known-good copy is also kept at `/etc/github-runner/resolv.conf.known-good`
so `runner-health` can restore resolution without a human.

## Networking convention

- The container's static IP last octet **matches its VMID**. The live runner is
  VMID `111` at `192.168.2.111/24` (`network_ip` in `terraform.tfvars`). Keep
  `container_id` and `network_ip` in sync when changing either.
- Changing `network_ip` updates the container in-place but re-provisions the
  runners (the `null_resource` connects over SSH to that IP), so generate fresh
  tokens and apply via `just runner-apply`.

## Storage

- The runner's root disk lives on the **4TB NVMe SSD**: `datastore_id = "nvme4tb-lvm"`
  (LVM-thin on VG `nvme4tb`), 64 GB. It was moved there from `local-lvm`.
  Live check: `ssh proxmox "sudo cat /etc/pve/lxc/111.conf"` → `rootfs: nvme4tb-lvm:vm-111-disk-0`.
- `datastore_id` is **ForceNew** in the bpg provider — editing it in
  `terraform.tfvars` and running `apply` would **destroy and recreate** the
  container. Move the disk out-of-band instead (Proxmox UI → Resources → Volume
  Action → Move Storage, or `pct move-volume 111 rootfs <target>`), then
  reconcile state with a refresh-only apply:

  ```bash
  terraform -chdir=terraform/lxc apply -refresh-only
  ```

  Only after that should `terraform.tfvars` be updated to match, so a normal
  plan comes back clean.

## Coding conventions

- Follow all rules in `.github/instructions/terraform.instructions.md`
- All sensitive variables (`github_runner_tokens`, `root_password`, etc.) must have `sensitive = true`
- Inject credentials via `TF_VAR_*` environment variables — never hardcode them
- `terraform.tfvars` and `*.tfstate*` are gitignored — do not commit them
- Run `terraform fmt` before any commit touching `.tf` files

---

## What NOT to do

- **Never hardcode** tokens, passwords, or API keys in `.tf` files or `terraform.tfvars`
- **Never commit** `terraform.tfvars` — it is gitignored for a reason
- **Never skip** `terraform plan` before `terraform apply`
- Do not set `unprivileged = false` unless Docker-in-Docker is explicitly required
- Do not add runner tokens to git history, even in environment files
